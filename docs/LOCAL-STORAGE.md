# Local storage and SQLITE_FULL repair

2026-10-15: the user reported Android SQLite error 13 (database or disk is full) when continuing from Find dit hjem in APK 1.0.13. The compiled AsyncStorage dependency was verified to use its default 6 MiB maximum. Auth sessions, profiles, public tariff histories and encrypted energy caches all shared this SQLite database. The address save updates Auth metadata (which persists the session) and then saves the profile, so either write can surface this error. The actual phone database size/free disk space was not inspected; no device was attached. The evidence supports a quota failure but does not rule out a physically full disk.

APK 1.0.14 increases the native maximum to 64 MiB via `AsyncStorage_db_size_in_MB=64`. The dependency's generated release BuildConfig confirms `64L`. This changes the cap on the existing database; it does not reset or rename the database, app package, keys or account.

`src/services/local-storage-cache.mjs` serializes optional cache writes and critical Auth/profile writes. Its conservative size estimates use twice the combined key/value string length plus per-entry overhead. Budgets are shared across users/households on the device:

- Public historical/current prices: 2 MiB, evicting the oldest allowlisted public price entries when necessary. These can be downloaded again.
- Independently encrypted energy period caches: 12 MiB. At the limit, new/replacement cache writes may be skipped; accepted values remain in memory and authoritative cloud records are unaffected. Existing encrypted rows/revision pins are not evicted. Root encrypted vaults, login, profile, preferences and keys are never selected for eviction.
- Auth/profile writes retry once on recognized SQLITE_FULL/quota errors after removing only public-price cache entries. Persistent failure shows readable local-storage guidance. Unrelated errors retain their original failure behavior. No `AsyncStorage.clear()` or app-data reset is used. Other non-cache storage remains outside these application budgets; this is not a guarantee against a physically full disk or arbitrary oversized legacy root snapshots.

Account/profile saves are still reported as successful only when their required writes complete. Cached electricity records remain ciphertext, with existing encryption/signature formats and cloud quotas unchanged. Avoid deleting encrypted root caches or SecureStore/recovery keys as a troubleshooting shortcut.

Tests: `test-local-storage-cache.mjs` reproduces the actual onboarding save failure using direct session storage, then succeeds through the resilient Auth/profile path. It covers concurrent budgets, public-only pruning, preservation of session/root/period revision pins, optional-write failure and genuine persistent-full errors. Existing profile, price cache, vault-client, period-record, address-client, SmartThings UI and widget regressions pass. TypeScript-only validation passes. All I/O in regression tests is synthetic; physical-device confirmation is still needed.

The native release uses `.tmp/storage-repair-release/index.native-release.js` through the optional `stromblik.entryFile` Gradle property, preserving the previously released SmartThings/widget app sources and excluding unrelated local charger work. When switching isolated entry paths, remove only obsolete generated onboarding-image copies from `android/app/build/generated/res/createBundleReleaseJsAndAssets/drawable-mdpi` before packaging; source assets and prior APKs must remain intact. This prevents old path-derived resource names accumulating in the APK.
