# Property geometry, sun and environmental information

2026-10-17 implementation. This supersedes the outstanding geometry/air/simulation notes in HOME-PROPERTY-TABS.md; previous release evidence remains historical.

## Sources and matching

- Address ID resolves through the existing DAR/KDS helper. BBR main-building IDs and their `jordstykke` relation identify the relevant parcel(s). MAT v3 Jordstykke provides registered area, cadastral number and land-registry-district ID. MAT Lodflade provides polygons separately. All rings are retained, including holes. Current registration/validity and `Gældende` status required.
- This is the building's registered parcel area, not automatically the sum of every parcel in a BFE and not an apartment's private garden. No remaining building allowance calculation. Cadastral outlines are indicative, not a boundary survey.
- GeoDanmark GEODKV **v2**, not v3, matches BBRUUID in both cases (live source contains uppercase UUIDs). Exact related buildings and a bounded spatial view are queried separately because this register does not support a root `or` filter. `Anlagt` records only. Each query is capped at 100 and rejects truncation.
- All geometry uses EPSG:25832 metres. Orthophoto WMS `https://api.dataforsyningen.dk/orto_foraar_DAF`, layer `orto_foraar`, uses the same bbox and a 900×675 JPEG. It is an actual top-down orthophoto, not a polygon drawn over an oblique photo. Latest mosaic, no unsupported capture-year claim.
- Provider keys remain server-only. Four modes reuse the existing `/api/address/search` function: `geometry`, `orthophoto`, `air`, `energy-label`. Matching development-server routes included. No database/auth change or extra Vercel function.
- Geometry cache: at most 100 addresses, one-hour TTL. Client memory: 40 entries, 15-minute TTL. Orthophoto disk caching reuses the bounded 20 MiB/80-file feature cache, separate `ortho-` filenames, refreshed monthly. No SQLite changes or broad cache deletion.

## Simulation

New Hus & sol tab. SVG projects actual footprints into a rotatable extruded building-mass model over the same orthophoto. SunCalc 1.9 uses radians and azimuth from south, west-positive; ground shadows use the opposite ENU sun direction. Danish calendar/time and DST offsets are used. Seasonal dates, a time slider, accessible increment/decrement, playback/pause and reset are available. Vertical gestures remain parent scrolling; horizontal drags rotate.

Height is explicitly estimated at 3 m per BBR floor, otherwise 3 m, capped at 60 m. Absolute GeoDanmark Z values are NOT treated as wall heights. Flat model roofs; no invented surveyed roof pitch, windows or facade detail. Ground shadows on level terrain only; trees, terrain, exact roof geometry and facade/roof shadow occlusion are not modelled. No solar panels, production, shade percentages or ROI. Missing exact main-building match does not generate a substitute house.

## Air quality

Public Danmarks Miljøportal DCAT metadata resolves the actual current WFS layer per pollutant. Dataset IDs still contain 2021 even though verified metadata/data are 2024. Never infer the model year from that ID. Fixed allowlisted WFS host and layer names. Small point bbox, exact containing polygon (holes respected), max five candidates, actual `Aarstal` and pollutant value required. NO2, PM2.5, PM10, O3 in µg/m³. Modelled annual averages for a grid cell, not current AQI or a measurement at the house. No unsubstantiated national average/health rating. Each pollutant can fail independently. Air lookup is independent of MAT/GeoDanmark availability.

## Energy label access boundary

EMOData requires separately issued credentials from Energistyrelsen, configured privately as server-only `EMODATA_USERNAME` and `EMODATA_PASSWORD`. Do not paste them into chat or EXPO_PUBLIC variables. Official access: https://ens.dk/analyser-og-statistik/energimaerkningsdata . Swagger: https://emoweb.dk/emodata/api-docs/swagger.json .

Adapter uses the documented `SearchEnergyLabelUID` with the BBR building UUID, not a fuzzy address or arbitrary BFE label. Swagger describes the UID as an OIS identifier; actual compatibility with current BBR UUIDs must be verified with EMOData access. UI supports each returned report's grade, valid-from, valid-until, provider status, building number and consultant. Explicitly distinguish unconfigured access, denied access and lookup unavailable. Empty arrays are treated as unavailable until provider success/no-result semantics can be verified; they do not prove a missing certificate. Reports are not silently merged or declared current solely by their expiry date. Missing data never imply label E or any other estimated class. Current local and production configuration have no EMOData credentials: actual authenticated report retrieval remains blocked/unverified. A direct unauthenticated provider probe confirmed HTTP 200 can contain `ResponseStatus.Status=ACCESS_DENIED`, which the adapter handles explicitly.

## Real 3D and DHM reconstruction, 2026-10-17

User approved implementation, scoped production deployment and APK installation. Replaces the SVG primary renderer with locally bundled Three.js r186 in Expo-compatible react-native-webview 13.15.0; SVG remains an explicit unsupported-device/error fallback. Local esbuild generation (`node scripts/build-home-3d.mjs`) embeds the engine and its MIT license in `src/generated/home3d-bundle.ts`, with no CDN scripts. The web implementation uses a sandboxed iframe. Only numeric model data and data-URI imagery enter the isolated document; CSP blocks external scripts/connections, native navigation is allowlisted to the synthetic document origin, file/universal access and DOM storage are disabled.

Height source: documented DHM WCS, https://datafordeler.dk/dataoversigt/danmarks-hoejdemodel-dhm/dhm-wcs/ . Existing server-only Datafordeler key successfully reads both `dhm_terraen` and `dhm_overflade` as GeoTIFF in EPSG:25832. New `mode=height&id=...` derives its bbox from the existing exact-address geometry; never accepts arbitrary provider URLs. Address function duration raised to 60 s; height client uses native-compatible AbortController with 45 s timeout. No auth/database changes or extra Vercel function.

Ground mesh follows DHM terrain. Building roofs use subdivided footprint triangulation (holes retained) sampling DHM surface within the footprint; local median smoothing reduces raster noise. Walls follow actual footprint edges and sampled ground/roof. Unsupported/out-of-bounds buildings retain explicitly estimated BBR heights. This is a **raster-derived approximation**, not surveyed roof planes, a facade scan or an architectural model. Overhanging vegetation, data age and raster resampling can affect roof shape. Acquisition year is not inferred. No invented windows, doors, textures or solar yield. UI reports measured-vs-estimated building counts and whether the main roof uses DHM.

Perspective camera with damped orbit, pinch zoom and reset. GPU directional-light shadow maps cover ground, roofs and walls; astronomical sun vectors use E/up/negative-N axes and are sampled every 15 minutes with smooth per-frame interpolation. Visible sun trajectory and sun marker; daylight/twilight/night lighting blend. requestAnimationFrame playback advances continuously, UI clock messages are throttled to 4 Hz. Static views redraw only on change/damping. Backgrounding pauses playback and rendering; unmount destroys the WebView. Fallback is visible, not silently presented as the improved model.

## Calibrated roof/facade photography

User requested reusing the detailed Overview skråfotos in the model and explicitly approved server deployment and APK installation. Keeps DHM geometry rather than presenting photo detail as a new geometry survey.

New `mode=model-photos&id=...` derives main building, terrain elevation and source imagery from the existing exact-address helpers. Reads bounded full-resolution COG crops, without upscaling, using the original source camera center, rotation, focal length, principal point and crop offset. At most five JPEGs, 1,024 px maximum output edge, 350 KB cap per image; missing height/calibration/source fails to a clearly simplified model. The gallery's existing photo contract/render version and approximate marker remain unchanged. Its source catalogue is shared internally; source URLs and credentials are never returned to the model client.

GPU projective mapping uses the calibrated perspective camera for each source, per-fragment front-face selection and depth-map visibility against actual model geometry. DHM surface outside building footprints provides conservative vegetation occlusion; it is not rendered as fabricated trees. Normals are oriented consistently, including courtyard walls. Model geometry/DSM can differ from imagery, and shrubs, overhangs or temporal differences may still appear in photographic surfaces. Occlusion is approximate, not a guarantee of unobstructed facade imagery.

Only the matched main building receives photographic materials. Unseen/rejected pixels and all neighbours remain neutral/estimated rather than wrapping one image across every wall. Photomodel/Forenklet toggle retains a clean sun-shadow interpretation: source photographs already contain capture-day lighting and shadows, which are not relit intrinsic textures. Ground aerial toggle remains independent. Actual capture years are displayed. Memory holds at most two photographic address bundles. Photos arrive through the existing document bridge without reloading/resetting the orbit camera.
