Raw provider errors/credentials are never returned.

The client does not fuzzy-match valuations by address. Multiple BFE numbers and assessment-property groups stay separate; amounts are never summed or arbitrarily picked across groups. Earlier backend compatibility only uses legacy BBR fields if there is exactly one unique BFE. VUR may lack newer assessments, and preliminary/final status is not exposed by this lookup: both limitations are shown explicitly, with a link to verify the current assessment in Vurderingsportalen. No market-price, tax calculation or ownership claim.

## Server setup

Create a Datafordeler account and IT system, then create an API key with access to public DAR/BBR GraphQL v3. Save it privately as **DATAFORDELER_API_KEY** on the backend; never use EXPO_PUBLIC_ or paste the key into chat. Local server environment and Vercel environment are separate. No secret/environment changes were performed by this implementation.

- Official access: https://datafordeler.dk/vejledning/brugeradgang/
- BBR v3 documentation: https://confluence.kds.dk/pages/viewpage.action?pageId=219513710
- GraphQL syntax/schema: https://confluence.kds.dk/pages/viewpage.action?pageId=187105434
- DAR address/building links: https://confluence.kds.dk/pages/viewpage.action?pageId=187105632
- Code lists: https://bbr.dk/kodelister

GET `/api/address/search?mode=bbr&id=<precise-DAR-address-UUID>&q=<saved-address>` uses the existing function to preserve the Vercel Hobby function count. The local server exposes the same contract. These are public register facts; no user account or ownership inference. Responses are no-store. Without the key, it returns 503/BBR_NOT_CONFIGURED. The API key is used only server-side against fixed official HTTPS endpoints and is never returned or logged. Provider/transport errors are sanitized.

The server downloads the official DAR/BBR v3 SDL schemas and parses them with server-only graphql@16.11.0, caching schemas for five minutes. Live verification established that provider introspection is disabled, so it is not used. Queries use both current registration and valid time and fetch scalar/enum fields. It matches DAR Adresse → exact BBR Enhed and related Bygning (preferring unit building references), then fetches related public records by explicit IDs. Multiple matches are displayed rather than arbitrarily choosing a home. Each relation is paginated with a 300-record cap, at most ten related building/ground/property IDs and a shared 24-second upstream deadline. Explicit DAF-AUTH-0005 authorization propagation failures receive at most two retries, 250ms apart, within that deadline. Provider guidance says newly created keys may need at least fifteen minutes to activate; live requests demonstrated intermittent 401s alongside successful reads. Supplementary failures keep primary records with warnings. Further land-register/energy-label data is not part of this BBR lookup.
