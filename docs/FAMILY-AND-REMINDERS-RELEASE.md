## Available client changes

- Mit hjem → Affald now places `Husk affaldet` above the calendar. Options include one day, one hour, three hours or two days before collection, and off. These are local phone notifications with sound and explicit OS permission. Each user's active household has its own preference; old user-level preferences are adopted when no scoped value exists. Enabling creates the Android notification channel before asking permission. Choosing another interval replaces scheduled waste notifications; unrelated price notifications are untouched. Notification taps only open Affald for the matching user/household.
- Calendars provide a date, not a collection time: the UI explicitly uses 07:00 Europe/Copenhagen. Calendar-day subtraction preserves Danish time across DST, even when the phone uses another timezone. Only available future calendar entries are scheduled; this is not a server push service or a continuous alarm-clock service. Android can delay notifications without exact-alarm permission. No actual future collection notification delivery was verified on the phone.
- A disconnected consumption card shows a short explanation and `Se dit forbrug`. Pressing it uses the existing authenticated Eloverblik/MitID connection flow, including return handling, checking existing grants and errors. Existing household Eloverblik connections remain household-owned; family members do not need a separate grant to read the same household's data.

## Family flow

Mit hjem → Familie lists members, their own names/emails, pending invitations and owner actions. Owners invite by email, resend/revoke invitations and remove regular members. New invitations expire after seven days; there are at most ten members/pending slots and a one-minute resend interval. Existing trusted members retain management authority during migration; newly invited members cannot manage the family.

The email leads to `/family.html?home=UUID`. Android App Links open an installed current app directly; the landing page offers the Android APK when no app is installed. Neither the link nor the APK contains a household encryption key or an authentication token. The recipient verifies their own email, explicitly accepts the matching invitation and, if new, enters their own first/last name. They skip re-entering the household address and connecting the existing household providers. Existing users keep their own profile. The selected household is remembered per account.

Only shared home fields are copied into `households.home_profile`: precise address/coordinates, municipality/postcode, grid-company identifiers and waste calendar. Names, email, personal thresholds and credentials are excluded. Members read the same household-scoped vault and consumption records through existing RLS and the existing membership-checked managed-key mechanism. Encryption formats and keys are not replaced. Previously downloaded information cannot be erased remotely when a member is removed, but new server access is denied. Removal cannot reclaim an already accepted invitation.
