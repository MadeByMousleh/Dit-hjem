Both live domains reject missing/invalid authentication on the new action with 401/no-store.

The existing authenticated Eloverblik API accepts `action:grid`. Household membership and the household-owned provider authorization are required before the provider is called. The provider request uses the documented `/meteringpoint/getdetails` JSON body. Only authorized E17 consumption meters are accepted; missing, partial, duplicate, mismatched or foreign-meter responses fail explicitly. Returned data are limited to meter ID, type, grid operator name/ID, grid area and DAR address reference, plus a checked timestamp. Provider credentials never reach the app.

The client stores this evidence inside the existing encrypted `state/import.gridEvidence`, preserving importer state with signed revision-checked writes. It is cached for 15 minutes and scoped to the household. It is not copied into public property caches. Meter DAR references must match the selected profile address. Multiple addresses or conflicting tariff profiles block automatic total-price calculation. Missing/null DAR references do not silently become an address match.

Name-only matching is insufficient for N1: the current supplier catalogue has N1 A/S - 131 (`n1_c`) and N1 A/S - 344 (`n1_344`). The resolver uses the provider's grid-area code to distinguish them; other companies require a unique normalized exact legal-company-name match. Only supported private-customer C profiles are selected; this is not proof of a particular customer's special tariff, reduced electricity tax or individual electricity contract. The supplier catalogue supplies DK1/DK2. Spot prices depend on that market area; network tariffs additionally depend on operator/profile.

Without an Eloverblik connection, the existing coordinate-based grid lookup is used with an explicit source label. Unknown/ambiguous results block price calculation rather than selecting N1/DK1 by default. The startup default-N1 warm-up was removed. The price hook tags responses by selected tariff, rejects late responses from a previous supplier and exposes no price series until the current selection matches. Historical usage/monthly totals are similarly tagged, and historical price fetching refuses an empty supplier ID. Cheap-hour statistics accept the authoritative resolved supplier instead of insisting on a potentially outdated profile ID.
